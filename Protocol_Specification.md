# Protocol Specification — Smash Arena

Версия: 0.1 (практика №1)
Транспорт: UDP, порт 9000
Упаковка: `#pragma pack(1)`, little-endian на проводе, никакого выравнивания

## Общий формат пакета

Каждый пакет состоит из **заголовка** (4 байта) и **полезной нагрузки** (0–255 байт).

```
 0           1       2           3           4 ...
+-----------+-------+-----------+-----------+----------------
|   type    |   seq (uint16)  |   size    |   payload
|  (uint8)  |                  |  (uint8)  |
+-----------+-------+-----------+-----------+----------------
 \___________ header __________/        \____ variable ____/
```

### Поля заголовка

| Поле | Тип | Размер | Описание |
|---|---|---|---|
| `type` | `uint8_t` | 1 байт | Тип команды. См. таблицу ниже. |
| `seq` | `uint16_t` | 2 байта | Порядковый номер пакета. Считает отправитель, монотонно возрастает, переполнение через 65535 допустимо. Используется для отладки и детекта потерь. |
| `size` | `uint8_t` | 1 байт | Размер полезной нагрузки в байтах. Сервер/клиент знают, сколько байт читать после заголовка. |

### Таблица типов

| `type` | Имя | Направление | Payload | Назначение |
|---|---|---|---|---|
| `1` | `MOVEMENT` | client → server | `MovementCmd` (3 байта) | Игрок сообщает направление движения |
| `2` | `SHOOT` | client → server | `ShootCmd` (5 байт) | Игрок сообщает об атаке |
| `3` | `STATE` | server → client | `WorldState` (переменный) | Снимок мира, рассылается 20 Гц |

Значения зарезервированы: `0` — недопустимо (используется как «пакет без типа»), `4..255` — для будущих команд (`CONNECT`, `DISCONNECT`, `PING` и т.д.).

## Payload типов

### MOVEMENT (type = 1)

Клиент сообщает серверу, в какую сторону двигаться.

```
 0       1       2
+-------+-------+-------+
| plrId |  dx   |  dy   |
|(uint8)|(int8) |(int8) |
+-------+-------+-------+
```

| Поле | Тип | Описание |
|---|---|---|
| `plrId` | `uint8_t` | ID игрока, от имени которого команда (0..3 на старте, расширяемо) |
| `dx` | `int8_t` | Направление по X: `-1` = влево, `0` = стоять, `1` = вправо |
| `dy` | `int8_t` | Направление по Y: `-1` = вверх, `0` = стоять, `1` = вниз |

Скорость и инерцию считает сервер, клиент только говорит «куда хочу». Полный пакет: **7 байт** (4 заголовок + 3 payload).

### SHOOT (type = 2)

Клиент сообщает об атаке.

```
 0       1       2       3       4
+-------+-------+-------+-------+
| plrId | wpnId | dirX  | dirY  | aimTargetId
|(uint8)|(uint8)|(int8) |(int8) | (uint8)
+-------+-------+-------+-------+
```

| Поле | Тип | Описание |
|---|---|---|
| `plrId` | `uint8_t` | Кто бьёт |
| `wpnId` | `uint8_t` | ID оружия/приёма. На старте: `1` = удар рукой, `2` = спецудар. Расширяемо. |
| `dirX` | `int8_t` | Направление удара по X (`-1`/`0`/`1`) |
| `dirY` | `int8_t` | Направление удара по Y (`-1`/`0`/`1`) |
| `aimTargetId` | `uint8_t` | ID цели. `255` = нет конкретной цели, бьём по направлению. |

Сервер на основе `dirX/dirY` строит хитбокс, ищет, кто в него попал, наносит урон. Полный пакет: **9 байт** (4 + 5).

### STATE (type = 3)

Сервер рассылает клиентам снимок мира.

```
 0       1..N
+-------+---------- ... ----------+
| count | PlayerState × count     |
|(uint8)|                          |
+-------+---------- ... ----------+
```

`count` — число игроков на арене (1..4 на старте, теоретически до 255).

`PlayerState` (8 байт на игрока):

```
 0       1   2   3   4   5   6   7
+-------+-------+-------+-------+-------+-------+-------+
| plrId |   x   |   y   |  vx   |  vy   |  hp   | dmg%  |
|(uint8)|(int16)|(int16)|(int8) |(int8) |(uint8)|(uint8)|
+-------+-------+-------+-------+-------+-------+-------+
```

| Поле | Тип | Описание |
|---|---|---|
| `plrId` | `uint8_t` | ID игрока |
| `x` | `int16_t` | Позиция по X на арене (диапазон подобрать под размер арены) |
| `y` | `int16_t` | Позиция по Y |
| `vx` | `int8_t` | Текущая скорость по X (для плавной отрисовки) |
| `vy` | `int8_t` | Текущая скорость по Y |
| `hp` | `uint8_t` | Здоровье (на старте не используется активно, задел на будущее) |
| `dmg%` | `uint8_t` | Накопленный урон, 0..255. Главный параметр для knockback. |

Пример пакета STATE для 2 игроков: **4 + 1 + 2×8 = 21 байт**.

## Порядок байт

Используем **little-endian** как нативный для x86. Поле `seq` (`uint16_t`) упаковывается напрямую через `memcpy` или `htons` в зависимости от реализации. На старте обе стороны на x86 — проблемы не будет. Если когда-нибудь появится ARM-сервер или мобильный клиент — придётся явно конвертировать через `htons`/`ntohs`.

## Соглашения

- Сервер отвечает клиенту `STATE` независимо от того, прислал ли клиент что-то в этом тике. STATE идёт по таймеру, а не в ответ.
- Клиент шлёт MOVEMENT с фиксированной частотой (на старте — 1 Гц по ТЗ, потом поднимем до 20 Гц).
- Клиент шлёт SHOOT только по факту нажатия.
- Пакет с неизвестным `type` сервер игнорирует и пишет в лог `[WARN] unknown type=X`.
- Пакет с `size`, не совпадающим с ожидаемым размером payload для данного `type`, отбрасывается.
- Никаких подтверждений доставки. Потерял пакет — ну и ладно, следующий придёт.

## Пример пакета (hex dump)

MOVEMENT от игрока 0 вправо:
```
01 01 00 03 00 01 00
│  │     │  │  │  └── dy = 0
│  │     │  │  └───── dx = 1 (вправо)
│  │     │  └──────── plrId = 0
│  │     └─────────── size = 3
│  └───────────────── seq = 1
└──────────────────── type = 1 (MOVEMENT)
```

SHOOT от игрока 2 ударом 1 вправо, без конкретной цели:
```
02 0A 00 05 02 01 01 00 FF
│  │     │  │  │  │  │  │  └── aimTargetId = 255 (нет цели)
│  │     │  │  │  │  │  └───── dirY = 0
│  │     │  │  │  │  └──────── dirX = 1
│  │     │  │  │  └─────────── wpnId = 1 (удар рукой)
│  │     │  │  └────────────── plrId = 2
│  │     │  └───────────────── size = 5
│  │     └──────────────────── seq = 10
│  └────────────────────────── type = 2 (SHOOT)
```

## Что в следующих версиях

- [ ] `CONNECT` (type = 4) — клиент сообщает nickname, сервер выдаёт `playerId`.
- [ ] `DISCONNECT` (type = 5) — корректный выход.
- [ ] `PING`/`PONG` (types 6/7) — замер RTT.
- [ ] CRC32 в заголовке (доп. задание практики №1).
- [ ] Сжатие `WorldState` (дельта-пакеты, отправка только изменившихся игроков).
