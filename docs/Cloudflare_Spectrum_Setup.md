# Cloudflare Spectrum: защита игрового UDP-порта (ПР №6, этап 3–4)

> **Статус этого документа — честно.** Подготовлено всё, что можно сделать без аккаунта Cloudflare: схема, порядок действий, правила файрвола origin, выбор уровня
> чувствительности с обоснованием, проверка сервера и клиента за прокси-эмулятором, ответы на вопросы. **Не сделано (нужны ваш аккаунт, домен и VM):**
> реальное создание Spectrum-приложения, скриншоты панели, тест с настоящим Cloudflare. Места для скриншотов помечены `ВСТАВИТЬ`; список — в разделе 7.

## 0. Важное ограничение: UDP в Spectrum — только Enterprise

По документации Cloudflare («Protocols per plan», страница обновлена 27.08.2026): Spectrum для произвольного **UDP** доступен **только на плане Enterprise как платная надстройка**; на Free его нет, на Pro и
Business доступны только SSH, Minecraft (и RDP на Business) — по одному приложению. Источник: <https://developers.cloudflare.com/spectrum/protocols-per-plan/>. Цены не публикуются (через менеджера).

Что с этим делать студенту (выберите вариант и **напишите в отчёте, какой именно**):
1. Спросить у преподавателя доступ к Enterprise-аккаунту / тестовой зоне с Spectrum — тогда выполнить разделы 2–6 как написано.
2. Если доступа нет — выполнить всё, что не требует Spectrum (раздел 5: файрвол origin, SPP-совместимость, локальная проверка через прокси-эмулятор `tools/udp_proxy.py`), и в отчёте прямо указать, что реальное
   приложение Spectrum на бесплатном плане создать нельзя (с цитатой документации выше). Выдавать эмулятор за Cloudflare нельзя — он демонстрирует только эффект «сервер видит адрес прокси».
3. Аналоги для UDP-игр у других провайдеров (например L4-прокси облачных провайдеров) устроены так же по схеме; в рамках этого задания требуется именно Cloudflare.

## 1. Схема

```
 игрок                          Cloudflare (anycast)                        origin: VM (cloud.ru free tier или другая)
┌────────┐   UDP game.example.com:9000   ┌────────────────────────┐   UDP 24680    ┌────────────────────────────────────────┐
│ клиент │ ───────────────────────────►  │ Spectrum-приложение    │ ─────────────► │ игра (Godot `--host` / secure_server)  │
│  Godot │ ◄───────────────────────────  │ UDP :9000 → origin     │ ◄───────────── │ слушает 24680, видит адрес Cloudflare  │
└────────┘   (шифрование X25519+AES-GCM  │ + Network-layer DDoS   │                │ файрвол: UDP 24680 только с диапазонов │
             сквозное: Cloudflare видит  │   Attack Protection    │                │ Cloudflare; SSH — только с вашего IP   │
             только шифртекст)           └────────────────────────┘                └────────────────────────────────────────┘
```

- Spectrum — прокси 4-го уровня: пересылает датаграммы, не разбирая их. Благодаря ПР №6 содержимое игры шифруется **между клиентом и игрой**, Cloudflare (и любой между ними) видит только заголовок и шифртекст.
- Порт на стороне Cloudflare (edge) **9000** (как в задании); порт origin — порт игры (по умолчанию 24680 для Godot, 27019 для C++ `secure_server_app`; можно сделать и 9000 — важно, чтобы совпадало с файрволом).

## 2. Подготовка origin

1. VM с публичным IP (например cloud.ru free tier), запустить игру на хосте с шифрованием: `godot --headless --path godot -- --host --port=24680 --encrypt=1` (или `secure_server_app 24680` для C++-сервера).
2. **Файрвол origin — только Cloudflare.** Если атакующий знает IP VM, он обойдёт прокси, поэтому UDP-порт игры открывается только для диапазонов Cloudflare (актуальные списки: <https://www.cloudflare.com/ips-v4> и
   <https://www.cloudflare.com/ips-v6>; они меняются — обновляйте правила по расписанию). Пример для Linux (ufw), порт игры 24680:
   ```bash
   sudo ufw default deny incoming
   sudo ufw allow from <ВАШ_IP> to any port 22 proto tcp          # администрирование — только вам
   for net in $(curl -s https://www.cloudflare.com/ips-v4; echo; curl -s https://www.cloudflare.com/ips-v6); do
     sudo ufw allow from "$net" to any port 24680 proto udp
   done
   sudo ufw enable && sudo ufw status numbered
   ```
   Также проверьте файрвол/security group облака (у cloud.ru — «группы безопасности»): то же правило там. Не должно быть правила «UDP 24680 с 0.0.0.0/0».
3. Проверка закрытости: с чужой машины `nc -u -z -v <IP_VM> 24680` (или любым UDP-сканером) — без Cloudflare ответа быть не должно; игра с прямого IP не подключается.

## 3. Настройка Cloudflare

1. Домен (или бесплатный поддомен) подключить к Cloudflare: добавить сайт, заменить NS-серверы у регистратора на выданные Cloudflare, дождаться статуса «Active».
2. В панели домена: **Spectrum → Create an application** (если пункта нет — на аккаунте нет Spectrum, см. раздел 0).
   - Application type: **UDP**; Edge port: **9000**; Origin: **IP VM : 24680**; Edge IP connectivity — IPv4 (по умолчанию); Proxy protocol — **Off** либо **Simple** (см. раздел 5, вопрос про бан по IP).
3. DNS-запись `game.example.com` создаётся при создании приложения (запись с проксированием Spectrum — оранжевое облако). Проверить: `nslookup game.example.com` возвращает адреса Cloudflare, а не IP VM.
4. В клиенте заменить адрес сервера `127.0.0.1` на `game.example.com` порт `9000`: `godot --path godot -- --join=game.example.com --port=9000 --encrypt=1`
   или `.\run_godot_demo.ps1 -Godot "…" -Role Join -Ip game.example.com -Port 9000 -Encrypt`. (Для C++-клиента: `secure_client_app game.example.com 9000`.)
5. Запустить клиент и посмотреть лог сервера: в строке «сессия установлена» будет **адрес Cloudflare, а не клиента** (раздел 5).

## 4. Правила защиты: Network-layer DDoS Attack Protection

Spectrum-приложения защищает управляемый набор правил **Network-layer DDoS Attack Protection** (Cloudflare включает его автоматически; кастомизация — через *ruleset override*: уровень чувствительности (Sensitivity) и
действие (Action) для всех или для отдельных правил; описание: <https://developers.cloudflare.com/ddos-protection/managed-rulesets/network/network-overrides/>). Названия пунктов панели могут отличаться в вашей версии
интерфейса — ориентируйтесь на документацию и впишите в отчёт то, что реально увидите.

| Параметр | Выбор | Обоснование |
|-|-|-|
| Sensitivity | **High (значение по умолчанию)** для всех правил | Наш трафик — малые датаграммы (десятки–сотни байт), десятки пакетов в секунду на клиента. Атака, которую стоит резать, на порядки больше (тысячи и миллионы пакетов в секунду), поэтому высокая чувствительность почти не даёт ложных срабатываний, а скорость реакции важнее: сервер на free-tier VM переживёт мало. Понижать (Medium/Low) стоит, только если в аналитике видны блокировки честных игроков. |
| Action (первые сутки) | **Log** | Сначала понаблюдать, что система считает атакой, не отрезая игроков; смотрим «Security → Events / DDoS analytics». |
| Action (после проверки) | **Block** | Для UDP-игры нет «человеческой» проверки (Challenge не применим): либо пропустить, либо отбросить. |
| Исключения | нет | Игра использует один порт; отдельные правила не нужны. |

Что важно честно записать в отчёт: эти правила защищают **канал** (объёмные L3/L4-атаки) и **скрывают IP**; они не заменяют шифрование и проверку пакетов в самой игре (подделку и повтор отбрасывает криптослой — Security.md), и не защищают от
атак, использующих легитимные пакеты игры на низкой скорости.

## 5. Сервер за прокси: что меняется (и проверка без Cloudflare)

- **Адрес отправителя.** Origin видит адрес **Cloudflare (edge)** вместо адреса игрока: в логе сервера, в таблице сессий (`NetNode.peers` / `std::map<"ip:port", Session>`), в любой «бан по IP». Следствия: бан по IP либо
  режет сразу всех, кто идёт через этот узел Cloudflare, либо не работает (нарушитель просто не имеет «своего» адреса); настоящего нарушителя нужно банить по идентификатору в игре (аккаунт/токен) или по адресу из SPP.
- **Simple Proxy Protocol (SPP) для UDP.** При включении Spectrum добавляет к **каждой** датаграмме заголовок 38 байт (магическое число `0x56EC`, адрес клиента 16 байт, адрес Cloudflare 16 байт, порт клиента 2, порт Cloudflare 2),
  а origin должен добавлять такой же заголовок к ответам; без разбора заголовка игра «сломается» (датаграмма начнётся не с байта типа). Документация: <https://developers.cloudflare.com/spectrum/reference/simple-proxy-protocol-header/>
  и <https://developers.cloudflare.com/spectrum/how-to/enable-proxy-protocol/>. В этой работе SPP **не реализован** (`Proxy protocol: Off`), поэтому реальный адрес клиента серверу недоступен.
- **Совпадение ключа сессии.** Таблица сессий — по `ip:port` отправителя. Если несколько игроков приходят с одного адреса Cloudflare и одного порта, ключи сессий конфликтуют. Проверьте в логе при двух клиентах: адреса должны различаться
  по порту. Если нет — нужен SPP или идентификатор сессии внутри протокола (в этой работе не сделано).
- **Лимит handshake** (4/с на хосте) считается по всем клиентам вместе — за прокси это не меняется.

**Локальная проверка (выполнена, без Cloudflare):** `tools/udp_proxy.py` — UDP-прокси между клиентом и сервером; для сервера все клиенты выглядят адресом прокси. Запуск:
```
python tools/udp_proxy.py --listen 27031 --target 127.0.0.1:27030 --quiet     # «Spectrum»: клиент идёт на 27031
secure_server_app 27030        # origin
secure_client_app 127.0.0.1 27031
```
Результат: клиент выполнил handshake и доставил выстрелы (ACK получены) через прокси — **шифрование и ACK/повторы работают за прокси**; в логе сервера адрес `127.0.0.1:<порт прокси>`, а не порт клиента
(пример: `[127.0.0.1:37331] сессия установлена`). Это демонстрирует эффект из раздела 5, но **не является тестом Cloudflare**.

## 8. Ответы на вопросы

- **Зачем закрывать origin для всех, кроме Cloudflare?** Иначе прокси можно обойти, ударив прямо по IP VM (адрес часто утекает: старые DNS-записи, логи, сканирование диапазонов), и DDoS-защита ничего не даст. Файрвол с диапазонами Cloudflare
  оставляет единственный путь — через прокси.
- **Что видит сервер в адресе отправителя после включения Spectrum и как это влияет на бан по IP?** Адрес Cloudflare вместо адреса игрока (если не включён SPP); бан по IP станет либо ударом по всем игрокам через этот узел, либо бесполезным; нужен SPP или бан по учётной записи.
