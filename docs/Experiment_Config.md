## Почему эмуляция задержки/джиттера/потерь встроена в сервер, а не через Clumsy

[Clumsy](https://jagt.github.io/clumsy/) — инструмент только под Windows
(драйвер WinDivert), недоступный в Linux-среде, где выполнялась сборка и
проверка этой работы. Задание явно допускает такой случай: *"если задержка
встроена в сервер, это явно фиксируется в отчёте"*. Поэтому `pong_server_app`
принимает флаги `--delay-ms`, `--jitter-min-ms`/`--jitter-max-ms`,
`--loss-percent`, `--seed` (см. `server/pong_server.cpp`) и сам вносит
искусственную задержку через `std::this_thread::sleep_for` перед отправкой
PONG, а потери — просто не отвечая на часть PING. Это даёт полностью
воспроизводимый (по `--seed`) и переносимый (Linux/Windows/CI) эксперимент,
не зависящий от внешнего инструмента.

**На Windows 11 с Clumsy** тот же эксперимент можно провести и "физически":
запустить `pong_server_app` без флагов (эмуляция выключена) и включить
нужный профиль Clumsy (Lag/Drop/Throttle) между `ping_client_app` и
`pong_server_app`, идущими на разных машинах или через `127.0.0.1` с
драйвером Clumsy на loopback. Формат CSV и вся последующая обработка не
изменятся.

## Обоснование тайм-аута 1000 мс

Максимальная искусственная задержка в самой тяжёлой серии `combined` —
100 мс (`--delay-ms`) + до 150 мс джиттера (`--jitter-max-ms`) = 250 мс
"наихудшего случая". Тайм-аут 1000 мс даёт четырёхкратный запас над этим
случаем: он достаточно велик, чтобы НЕ путать "просто медленный, но живой"
ответ с потерей, и при этом достаточно строг, чтобы в серии `loss_5`
(намеренные потери) реально потерянные пакеты не смешивались с ожиданием.
Значение совпадает с рекомендованным в самом задании ("Тайм-аут — 1 000 мс
либо обоснованное в отчёте значение").

## Параметры серий

Все серии запущены последовательно скриптом `run_experiments.sh`
(один и тот же `pong_server_app`, каждый раз перезапущенный с новыми
флагами и новым `--seed`, чтобы потери/джиттер каждой серии были
воспроизводимы независимо):

| Серия | Флаги `pong_server_app` | seed |
|---|---|---|
| `baseline` | *(нет)* | 100001 |
| `delay_50` | `--delay-ms=50` | 100002 |
| `delay_100` | `--delay-ms=100` | 100003 |
| `jitter` | `--jitter-min-ms=50 --jitter-max-ms=150` | 100004 |
| `loss_5` | `--loss-percent=5` | 100005 |
| `combined` | `--delay-ms=100 --jitter-min-ms=50 --jitter-max-ms=150 --loss-percent=5` | 100006 |

Генератор случайных чисел — `std::mt19937`, инициализируется явно переданным
`--seed` (см. `ParseArgs`/`main` в `server/pong_server.cpp`); без флага сервер
сам генерирует seed через `std::random_device` и печатает его в консоль
(`Параметры эмуляции: ... seed=...`) — именно так были зафиксированы seed'ы
в таблице выше.

## Как повторить эксперимент

```bash
g++ -std=c++17 -O2 protocol/protocol.cpp telemetry/telemetry.cpp telemetry/transport.cpp \
    client/ping_client.cpp -o ping_client_app
g++ -std=c++17 -O2 protocol/protocol.cpp telemetry/transport.cpp \
    server/pong_server.cpp -o pong_server_app

./run_experiments.sh          # прогоняет все 6 серий, пишет docs/latency_samples.csv
python3 analysis/analyze_latency.py   # печатает таблицу, строит docs/graphs/*.png
```

На Windows 11 (PowerShell/cmd, MinGW или MSVC) — те же команды со сборкой,
как в README (`g++ ... -lws2_32` или `cl ...`), и `run_experiments.sh`
заменяется ручным запуском `pong_server_app`/`ping_client_app` в двух
окнах терминала для каждой серии по очереди (сам скрипт — bash, для
Windows его можно прогнать через Git Bash/WSL без изменений).
